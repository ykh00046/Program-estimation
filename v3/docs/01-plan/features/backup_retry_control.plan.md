# Backup Retry Control 계획서

> **PDCA Cycle**: #41
> **작성일**: 2026-06-18
> **선정 근거**: PDCA #35 `backup_hardening`의 명시적 최우선 후속 과제

## Executive Summary

| 관점 | 내용 |
|---|---|
| Problem | 실패 백업은 로컬 큐에 안전하게 남지만 사용자가 대기량을 확인하거나 즉시 복구할 UI가 없다. |
| Solution | 관리자 화면에 Google Sheets 설정 진입점을 복원하고 대기 건수·비동기 재시도 제어를 제공한다. |
| Function/UX Effect | 설정 화면에서 대기량을 즉시 확인하고 앱 멈춤 없이 한 번의 클릭으로 재전송한다. |
| Core Value | 자동 복구를 기다리지 않고 운영자가 데이터 보호 상태를 직접 확인·회복할 수 있다. |

## Context Anchor

| Anchor | 내용 |
|---|---|
| WHY | 보존된 실패 백업을 관찰·복구할 운영 제어가 필요하다. |
| WHO | 생산 기록과 Google Sheets 백업을 관리하는 관리자 |
| RISK | 네트워크 재시도가 UI를 멈추거나 실패 큐를 유실하는 것 |
| SUCCESS | 대기량 표시, 비동기 재시도, 성공 시 비움, 실패 시 보존, 회귀 0 |
| SCOPE | 설정 다이얼로그, 관리자 진입점, UI/모델 통합 테스트 |

## 1. 배경 및 우선순위

후보를 사용자 가치, 긴급도, 검증 가능성, 구현 위험으로 비교했다.

| 후보 | 가치 | 위험 | 결정 |
|---|---:|---:|---|
| 백업 대기량/즉시 재시도 | 높음 | 낮음 | **이번 사이클** |
| 일괄 생성 진행률/취소 | 중간 | 중간 | 후속 |
| 미결 발주 대시보드 | 중간 | 낮음 | 후속 |
| 바코드 LOT 입력 | 높음 | 높음 | 장비·포맷 정의 후 |
| SPC 배합 편차 분석 | 높음 | 높음 | 통계 기준 합의 후 |

백업 재시도는 이미 구현된 JSONL 큐를 완성하는 마지막 운영 제어이며 데이터 유실 위험을 즉시 낮춘다.

## 2. 요구사항

### 기능 요구사항

- **FR-01** 관리자 모드에서 Google Sheets 백업 설정을 열 수 있다.
- **FR-02** 설정 화면은 현재 대기 행 수를 표시한다.
- **FR-03** 대기 행이 있을 때만 `지금 재시도`를 활성화한다.
- **FR-04** 재시도는 기존 `GoogleSheetsBackup.backup_records([])` 계약을 사용한다.
- **FR-05** 재시도는 백그라운드 워커에서 실행하며 중복 실행을 막는다.
- **FR-06** 성공/실패 결과와 갱신된 대기 건수를 사용자에게 알린다.

### 비기능 요구사항

- 모델/큐 파일 형식 및 자동 백업 경로를 변경하지 않는다.
- 실패 시 기존 대기 데이터가 보존되어야 한다.
- 외부 Google API 없이 결정론적 테스트가 가능해야 한다.

## 3. 성공 기준

- **SC-1** 관리자 다이얼로그에 백업 설정 버튼이 있고 설정 창을 연다.
- **SC-2** 0건/복수 건 상태가 정확히 표시되고 버튼 상태가 연동된다.
- **SC-3** 재시도 작업이 기존 `FunctionWorker` 경로로 실행된다.
- **SC-4** 성공 시 0건, 실패 시 기존 건수를 표시한다.
- **SC-5** 관련 신규 테스트와 전체 회귀 테스트가 통과한다.

## 4. 범위 제외

- 주기 스케줄러, 큐 항목 편집/삭제, 재시도 횟수 정책
- Google Sheets API 또는 JSONL 스키마 변경
- 바코드/SPC/발주 기능

## 5. 위험 및 완화

| 위험 | 완화 |
|---|---|
| 실행 중 창 종료로 QThread 파괴 | 실행 중 닫기/취소를 차단 |
| 재시도 중복 클릭 | 워커 busy 위젯으로 버튼 비활성화 |
| 설정 미저장 값과 재시도 혼동 | 재시도는 저장된 설정만 사용한다고 툴팁 명시 |
| 사용자 작업과 충돌 | 기존 전역 큐 Lock 및 기존 flush 계약 재사용 |
